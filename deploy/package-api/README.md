# Package API deployment

Review and render `nginx-legacy.conf.template` only for the dedicated old API hostname. Use `envsubst` with an explicit whitelist `${PACKAGE_API_HOST} ${PACKAGE_UPSTREAM}` so Nginx variables remain intact. Supply valid TLS certificate directives before `nginx -t` and reload. The trailing proxy URI preserves the full path and query below `/jeecg-boot/package-legacy/`; Host, original URI and client IP are set by the proxy. Do not expose the upstream port publicly.

Set `jeecg.package-management.trusted-proxies` to the exact immediate proxy IP addresses (comma separated), never client subnets or `*`. Set `jeecg.package-management.profile-root` to the persistent source profile directory, including historical `upload/` and `download/` trees. The module serves `/profile/**` through the dedicated namespace; do not symlink outside this root. The source helper has a 50 MiB ceiling, but source effective servlet limits are 10MB per file and 20MB per multipart request. Opt in to `spring.servlet.multipart.max-file-size=10MB` and `spring.servlet.multipart.max-request-size=20MB` in the candidate host profile (the host currently defaults to 10MB aggregate). Nginx allows 21m envelope headroom; Spring remains authoritative for the 20MB aggregate. Small-file behavior is tested; large-limit behavior needs deployment validation. Existing frontend hosts call the normal authenticated `/jeecg-boot/package-admin` namespace.

`package-management.properties` supplies integration environment bindings documented in Task 2. Additional bindings are `PACKAGE_PROFILE_ROOT` and `PACKAGE_TRUSTED_PROXIES`. Keep all secrets outside Git. Configure `server.forward-headers-strategy=none` at this trust boundary: the module sanitizes forwarding headers for the legacy namespace, and trusted proxy metadata must not first be accepted globally from arbitrary peers. Confirm existing host proxy settings before enabling this value.

Initialize explicit tenant/user identity and resource-owner mappings with the reviewed migration scripts. Unknown historical owners remain denied in management. Configure the host Quartz job UI with class `org.jeecg.modules.packagemanagement.job.PackageStoreJob` and the desired approved cron; this code does not create or activate production jobs automatically. Swagger group `package-management` contains both namespaces; do not publish private Swagger on the old API host.

Before switching DNS or proxy routing: back up current Nginx config and database; copy historical uploads; verify the identity preflight; run the documented Maven gate and local HTTP suite against the candidate; verify integration variables using nonproduction doubles. For rollback restore the previous dedicated Nginx upstream and reload after `nginx -t`, disable the new Quartz job, and retain new upload/database records for reconciliation. Schema migrations are additive; do not drop tables or delete uploaded files during rollback. SQL transactions cannot roll back NPM, push or Elasticsearch effects, so reconcile failed external operations from logs before retrying. No production routing changes are performed by this delivery.
