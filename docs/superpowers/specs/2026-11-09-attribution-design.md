# 归因管理独立功能接入方案

## 1. 接入方式

推荐在现有 JEECG 服务中装配独立 Maven 模块 `jeecg-module-attribution`，Java 包为 `org.jeecg.modules.attribution`，使用独立的 `attr_` 业务表，前端目录为 `src/views/attribution`。

| 方案 | 取舍 | 结论 |
| --- | --- | --- |
| 独立 Maven 业务模块，随 JEECG 部署 | 菜单、登录与部署统一；业务代码和数据边界明确 | 推荐 |
| 加入现有应用包管理模块 | 装配较少，但应用、接口、权限和旧客户端逻辑耦合 | 不选 |
| 新建独立归因服务 | 可独立扩容，但增加认证、网络与部署工作 | 当前无此必要 |

新增一级菜单“归因管理”，路由 `/attribution`，直接展示应用管理页。只有一个运营页面；新建和编辑共用弹窗，多条 Offer 通过行内展开查看。读写、诊断及受控操作分别授权，菜单可见性不能替代服务端权限。

本次包含前端、后端、增量 SQL、菜单及权限脚本、配置样例、测试和运行说明。现有应用包管理与站点分流的数据不自动迁入归因模块。

## 2. 已核实的项目适配点

- 后端根目录为 `upstream/JeecgBoot/jeecg-boot`；独立业务模块可挂载在 `jeecg-boot-module/pom.xml`，并由 `jeecg-module-system/jeecg-system-start/pom.xml` 引入。现有 `jeecg-module-package` 已采用此方式。
- 前端目录为 `upstream/JeecgBoot/jeecgboot-vue3`，使用 Vue 3、TypeScript、Ant Design Vue 和 JEECG 动态菜单。
- 管理前端的 `defHttp` 默认读取 JEECG `Result.result`。管理接口采用宿主响应和分页规范，文档明确标为建议的管理路径改为 `/attribution-admin`；公开 resolve 保持原始固定路径和九字段平铺响应。
- 当前应用包管理权限依赖旧用户映射，不能直接作为新归因模块的身份服务。归因模块使用 JEECG 登录用户、服务端验证的有效租户成员关系和自身应用授权。
- 现有 GeoPort 直接读取多种转发头，不能直接视为可信国家来源。新功能初始只开放 OS；部署可信代理及地理数据适配后才开放 COUNTRY。已有 COUNTRY 规则在来源不可用时按未知处理。
- 数据库上下文、菜单导入及部署方式已有本地记录；开发时使用独立增量脚本，不重建已有业务库。中文 SQL 显式使用 utf8mb4。
- 工作区已有 README、AWS 部署等未提交修改，本功能不覆盖这些修改。

## 3. 页面行为

应用列表保持文档的五列：应用名、渠道名、兜底地址、Offer 地址、操作。服务端按应用名或渠道名搜索，按当前登录作用域分页。地址省略并可查看全文，不直接跳转推广地址。

每个应用一行，显示当前明确绑定的编辑渠道。0 条普通 Offer 显示“—”；1 条显示地址；多条显示首条和“查看(n)”，行内按保存顺序展示全部地址、条件和权重。0 权重仍计入数量。读取失败显示重试，不能伪装成空数据。

弹窗约 800 px，小屏自适应，内容内部滚动，固定取消和保存按钮。只编辑应用名、渠道名、必填兜底 URL 和 Offer 卡片；编码、内部 ID、版本与幂等信息隐藏传输。

每条卡片包含目标 URL、非负整数权重和本条条件。首条默认权重 1，后续新增默认 0。每条独立设置 AND/OR、OS/COUNTRY、IS/IS_NOT 和值集合；条件为空代表不限。删除卡片只解除当前渠道的受管绑定。

存在 Offer 时至少一个权重大于 0；空 Offer 数组合法。保存失败和版本冲突保留用户输入，字段错误定位到卡片。取消直接放弃本次编辑。保存成功后关闭并刷新，不新增发布步骤，也不增加应用删除按钮。

## 4. 分流与历史稳定

一次点击只读取一个不可变配置版本。遍历全部绑定，过滤掉权重 0、不可投递和条件不匹配的条目，对剩余候选按相对整数权重选择；排序仅决定累计区间。无候选使用同应用默认地址。

OS 标准值为 ANDROID、IOS、WEB；无法可靠识别时为 UNKNOWN。未知属性的 IS 和 IS_NOT 均为 false，OR 可由另一已知条件命中。COUNTRY 只接受受支持的 ISO 两字母代码，并依赖可信来源。

使用作用域、应用、渠道、配置版本和 clickRef 构造稳定抽选输入，使用数据库唯一约束保存首次决策。相同 clickRef 或入口幂等键的并发请求复用首次结果。resolve 不重新抽选，调整权重和条件只影响新点击。

原目标下架、禁用、到期或平台不符时，只降级到当前同应用安全默认地址，保留历史广告事实。无安全目标返回 503。安全撤销状态独立于配置版本，内部版本回退不能使已撤销 URL 复活。

## 5. 数据与事务

新增逻辑存储覆盖：应用、渠道、Offer、渠道 Offer 绑定、不可变配置版本、管理保存幂等记录、真实点击及归因状态版本、令牌绑定、模拟快照、应用授权、URL 许可与撤销、审计。物理表按访问和约束需要组织，统一 `attr_` 前缀。

条件和权重保存在渠道 Offer 绑定层。编辑共享 Offer 的 URL 使用 copy-on-write。保存只改变当前渠道及 SIMPLE_UI 受管集合，保留其他渠道和未展示配置；无法无损适配复杂历史配置返回 409。

聚合保存采用单个关系型数据库事务：验证身份及资源归属、字段、URL、受管集合和期望版本；写新版本及审计；CAS 切换活动版本。事务失败不生效半配置。

编辑请求显式发送 removedBindingIds。遗漏已有受管绑定、重复 clientKey/bindingId、同时保留和移除同一绑定均拒绝。幂等键绑定调用者、路由和请求摘要，同键同内容返回首次结果，不同内容返回 409。

对外所有 ID 均使用字符串。设备和安装标识只保存带用途、应用和作用域隔离的 HMAC 摘要；令牌只保存安全摘要。历史快照不随配置编辑级联删除。

## 6. 接口与身份

管理接口使用 JEECG 登录态和独立 `attribution:*` 权限，提供列表、行展开、编辑读取、聚合创建及更新。前端分页适配 pageNo/pageSize 和 records/total。展开请求带 configVersion，版本不同返回 409。支持诊断接口不增加运营页面。

公开接口固定为 `POST /api/v1/attribution/resolve`，不因管理接口适配改变。成功响应严格包含 clickRef、resolveToken、applicationCode、promotionCode、resolutionState、parameterSource、destinationUrl、afLinkParams、fbLinkParams 九个字段；错误按文档 code/message/traceId 及 HTTP 状态返回。响应禁止缓存，日志不记录令牌和设备明文。

ATTRIBUTION_TOKEN 只读取可信真实快照，验证主体、应用、渠道、点击、用途及到期时间。无效或过期返回 401，绑定不符返回 403，无记录返回 404。PENDING、MATCHED、UNMATCHED 均保持 REAL，真实缺失字段不补 mock。

DEVICE_ID/INSTALL_ID 只能生成或读取本应用稳定模拟快照，始终为 FALLBACK/SIMULATED；包含文档规定的七个 AF 参数和六个网站参数，所有模拟值使用 mock_ 前缀，无真实点击时 clickRef 为 null。模拟请求携带非空 clickRef 必须有额外的主体关联证明。真实与模拟存储、权限及状态互相隔离。

公开入口需要独立主体认证。实现一个可替换的服务端主体验证边界和受控签发/绑定能力，凭据绑定应用、主体、用途和时效；应用编码、设备 ID、安装 ID、共享 App secret 均不能替代认证。初期受控调用者使用服务端签发的主体凭据进行端到端验证，具体移动端身份提供方及商店/深链交付另按实际接入配置完成，不能虚构已有集成。

点击采集为受控入口，由后端确定应用和渠道。只接受经验证的广告事实；不凭“Meta 渠道”名称认定真实媒体，不将任意调用者提交的广告字段标记为可信。归因证据更新和纠正使用单独受控操作及追加审计。

## 7. 安全配置与启用

目标地址必须为 HTTPS，服务端验证实际主机、端口、用户信息和控制字符；阻断本地/内网地址及未获准域。域许可和 URL 下架由受控配置或操作维护，运营弹窗不增加 allowedHosts。新域未批准时显示明确字段错误。

对解析、点击和保存分别实施权限、请求大小及合理容量限制。公开身份和 App 限流需要多实例可用的实现，并返回 429 和 Retry-After。同步链不抓取远端推广地址，不实时反查第三方广告平台。

新归因流量处理默认关闭，按应用白名单启用；菜单和管理表单可独立配置，表单保存即更新活动配置，无额外发布动作。通过受控环境开关验证完整链路后再启用对外流量。

HMAC/令牌密钥、URL 许可、可信代理、国家来源、保留期和限流参数通过服务端配置管理。缺关键安全配置时拒绝启动对应公开能力或拒绝请求，不生成内置生产密钥，不把未接入的真实媒体交付标记为完成。

## 8. 验收与交付

1. 规则测试覆盖 RT01–RT15：独立条件、AND/OR、多值 IS_NOT、未知值、0 权重、空 Offer、全部候选与加权边界。
2. 数据库集成测试覆盖聚合事务、CAS 版本冲突、显式移除、幂等同键异载荷、跨租户/应用/主体拒绝、共享 Offer 修改隔离。
3. 并发测试覆盖同 clickRef 首次写和同模拟标识首次写，确认唯一首次快照及失败事务后重新读取；验证 100 个重复点击请求。
4. 公开协议测试覆盖九字段、字符串大 ID、真实三状态、两类模拟、过期令牌、无记录、URL 安全降级与数据库失败，不以 HTTP 200 冒充成功。
5. 前端验证覆盖 0/1/多 Offer、行展开、独立条件、错误定位、失败输入保留、移动端弹窗和只读权限。
6. 执行目标模块及启动模块构建、前端构建，并在可用本地环境执行增量 SQL、菜单和端到端联调；提供运行与客户端接入说明。

性能容量、SLA、实际媒体回调、移动端商店透传、生产数据保留及密钥轮换策略需要部署方的实际配置和验证。本次代码与测试应区分已验证的受控链路与尚未接入的外部能力，不宣称已经压测、会签或投产。
