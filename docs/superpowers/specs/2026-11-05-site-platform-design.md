# 多站点与分流平台设计

日期：2026-11-05

状态：用户已确认聊天中的模块拆分与架构边界；本文将其固化为项目基线。

## 目标与边界

以 JEECG 承担管理后台，建设域名绑定、多站点配置、基础分流、访问统计、受控业务 API、权限审计和配置发布回滚。

首期站点代表已有网站及其目标地址，不包含完整网站页面搭建器。自然语言操作先限定在测试环境，通过受控接口生成变更草稿。

开发基线选择 JeecgBoot 开源版 v3.9.5，前后端采用同一标签，后台采用单体部署，入口分流服务独立。2026-11-06 已接入源码并完成本地基线；第一阶段资源模块的实现与验收见 `docs/deployment/site-resources-runbook.md`。版本选择依据见 `docs/baseline/version-selection.md`。附加组件与生产补丁仍须核验；官方展示能力不视为已交付能力，须结合选定版本源码与授权逐项验收。

## 八个模块

| 模块 | 职责 | 首期范围 |
| --- | --- | --- |
| 基础资源 | 租户、组织、用户、角色、环境及资源归属 | 身份与租户隔离、站点授权 |
| 域名与分流 | 域名归属验证、证书状态、路由规则 | 域名绑定、路径与权重分流、默认目标 |
| 多站点管理 | 站点、目标地址、站点配置 | 已有站点登记及启停配置 |
| 统计分析 | 访问统计、API 指标展示 | 站点及域名访问量、规则命中、错误 |
| 定制 API 平台 | 业务接口、调用凭证、授权及调用记录 | 固定业务 API、凭证授权、限流 |
| 自然语言操作 | 提案生成、差异展示、受控工具调用 | 测试环境草稿生成与验证 |
| 防崩机制 | 环境隔离、备份恢复、沙箱及风险校验 | 环境凭证隔离、操作限制、恢复验证 |
| 发布与变更管理 | 草稿、校验、审批、发布、节点确认、回滚及审计 | 配置版本全流程 |

## 运行架构

1. 管理后台：管理资源、权限、草稿、审批与发布记录。
2. 流量执行服务：读取已发布的不可变配置快照，执行路由和分流，保留最近可用版本。
3. 数据采集链路：异步采集访问与 API 指标，供后台查询。

后台不可用或采集失败不得阻断已发布路由。首期采用模块化后台与独立入口服务，不按每个业务模块拆微服务。

## 配置与发布约束

- 草稿、审批记录、发布版本和运行版本分别存储；发布版本不可原地修改。
- 审批绑定配置内容摘要与版本；内容变化后审批失效。
- 发布前检查域名归属、目标地址、规则冲突、授权范围及默认目标，并运行规则模拟。
- 域名按规范化后的主机名保证唯一归属；解除绑定或转移归属属于受审计变更。
- 规则优先级必须确定；权重分配仅在匹配的同一规则目标集合内执行。
- 入口服务上报实际运行版本；控制台区分待生效、部分生效、已生效和失败。
- 配置回滚通过重新发布历史可用快照完成，保留新的发布及审计记录。
- 多节点发布可能短时并存版本，首期不承诺全局原子切换；验收必须覆盖部分节点失败。
- 目标地址限制为批准的 HTTP/HTTPS 目标；禁止脚本协议，限制重定向循环和越权目标。
- 证书过期或绑定无效时不得将路由标为可安全上线；证书自动签发不纳入首期承诺。

## 权限与 AI

服务端在接口读取、写入、导出、批量操作和 AI 工具调用中执行租户、站点及字段授权；页面隐藏不作为授权依据。

AI 无生产发布凭证、数据库直连权限、任意脚本执行权限及插件安装权限。生产写入由受控发布服务执行，权限变更与凭证管理使用单独授权。

风险按环境、操作类型、数据范围、外部副作用和可恢复性判断。字段结构、生产 API、权限、数据隔离、核心分流、删除、批量修改、脚本与插件均纳入人工审批。高危生产变更由与提交人不同的授权人员复核。

## 三类记录

- 访问统计：站点、域名、规则版本、命中结果、访问来源及错误。
- API 监控：接口、状态码、延迟、调用量及限流结果。
- 变更审计：操作者及代理身份、租户、环境、资源、变更前后摘要、审批人、发布版本和执行结果。

首期独立访客以匿名标识估算，不能宣称精确人数；采集不记录 API Key、认证令牌或完整敏感请求体。审计使用受限追加写入，业务角色不可修改或删除。

## 回滚与恢复

首期承诺配置版本回滚。程序版本、数据库结构、业务数据及外部调用不包含在此承诺内。备份用于灾难恢复，恢复前明确恢复点和数据覆盖范围，并在测试环境验证。

不得对所有失败请求自动重试；只有确认幂等或具备幂等键的操作才可配置重试。

## 首期验收

1. 两个租户及不同站点的读取、修改、导出和 AI 调用越权均被拒绝。
2. 未验证归属的域名不能发布，重复归属被拒绝。
3. 域名、路径、权重规则及默认目标有确定结果，可模拟并验证权重分布。
4. 草稿不影响线上；审批后修改内容不能复用旧审批。
5. 已发布规则在后台停止或采集失败时继续服务；服务重启可恢复最近有效配置。
6. 节点发布失败可见，回滚恢复历史配置并产生新审计记录。
7. 统计可按站点及域名筛选；API 越权和超限可观察。
8. 测试 AI 可提交草稿，无法获得生产写入、脚本执行和授权能力。
9. 备份在测试环境完成一次可复现的恢复演练。

## 后续范围

地域和用户组分流、完整页面搭建器、通用 API 编排、OAuth、多环境 AI 开放及自动证书签发分期设计。用户组分流先明确访客身份来源；地域分流先明确地域数据来源和可信代理边界。
