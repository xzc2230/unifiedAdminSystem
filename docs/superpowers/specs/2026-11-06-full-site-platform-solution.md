# 域名、分流、多站点、统计及定制 API 完整建设方案

日期：2026-11-06。

本文是需求覆盖与分阶段建设方案，不是功能已完成声明，也不是可直接执行的逐文件编码清单。基于当前 JeecgBoot v3.9.5 项目，补充原方案中完整站点搭建、地域与用户组分流、OAuth、API 版本与重试等扩展需求。现有资源模块保留；各子系统启动开发前分别形成设计与代码实施计划。

已确认：流量使用**反向代理，浏览器保留当前访问域名**。站点需配合代理部署，登录、Cookie、绝对链接、WebSocket、上传及重定向均纳入兼容验收。

## 1. 当前状态与范围

本方案覆盖用户清单全部 17 个功能组，后文每项均有实现内容与验收标准。

| 范围 | 当前证据 | 本次建设范围 |
| --- | --- | --- |
| 站点、目标、域名 | `siteplatform/ResourceController.java` 已提供登记、DNS TXT 验证、成员与审计接口 | 保留并接入真实发布、证书与入口执行 |
| 用户、角色、菜单 | JEECG 系统模块可复用；资源模块另做租户与站点校验 | 扩展到站点页面、数据、发布、统计、API 所有入口 |
| 定制 API | `modules/openapi` 有接口、AK/SK、授权、日志等源码 | 核验后复用，补业务模型、字段隔离、版本、限流、OAuth 与重试 |
| 分流、站点页面运行时、访问统计 | 当前资源模块没有交付这些运行能力 | 新开发并单独验收 |
| 完整发布、灰度、回滚 | 尚未交付 | 统一发布服务，供路由、页面、流程、API 复用 |

现有 `/monitor/route` 是 JEECG 微服务网关管理入口，不等于本方案的业务站点分流。现有后台菜单、在线表单及登录统计不能直接视为多站点页面运行时或站点 PV/UV。

依据：`docs/baseline/capability-matrix.md`、`docs/deployment/site-resources-runbook.md`。原资源阶段的公共 DNS、真实多账号浏览器及生产最小授权验收仍需完成。

## 2. 架构选择与两台服务器

建议继续采用“JEECG 模块化管理后台 + 独立流量执行服务 + 异步采集”。与全部生成 Nginx 配置相比，独立执行服务更便于规则模拟、用户组判断、按版本确认与追踪；代价是必须建设并维护代理服务。与引入整套网关/分析产品相比，本方案组件数量较少，但规则、页面运行时、发布及指标仍需要开发，不能依靠后台菜单配置直接完成。

| 位置 | 服务 | 职责 |
| --- | --- | --- |
| 服务器 A：中间件 | MySQL 8、Redis 7.2 | 业务配置、版本、聚合指标；缓存、限流、受控事件暂存 |
| 服务器 B：应用 | Nginx | HTTPS、后台静态资源、已登记业务域名入口、请求大小与连接限制 |
| 服务器 B：应用 | JEECG Java 21 后端 | 资源管理、编辑、审批、发布、指标聚合、受控 API 与任务 |
| 服务器 B：应用 | 独立流量执行服务 | 保留域名反向代理、规则执行、健康检查、快照与本地日志 |
| 服务器 B：应用 | 站点运行时 | 渲染已发布页面、菜单与表单；与后台编辑界面分开构建 |

站点运行时可先用独立 Vue3 构建产物及受限的运行 API；访问量增长后再拆独立服务。文件先存 B 的版本目录与上传目录，异机备份；不把用户上传文件与不可变发布产物混放。

建议端口：B 对外 80/443；后台 `127.0.0.1:18080`，流量执行服务 `127.0.0.1:18090`。A 的 3306/6379 仅允许 B 私网访问。后台、业务站点和内部节点接口使用不同入口及认证范围。

流量执行服务建议采用 Java 21 独立工程，使用与已锁定 Spring 依赖兼容的响应式代理组件；选定依赖后做流式传输与压力验证，再固定版本。不得直接将当前单体后台配置成流量入口，或直接复用未经隔离的微服务路由接口。

执行节点从受认证的内部接口拉取已发布快照，并在 B 本地原子落盘，使用最近有效配置重启。路由判断不逐请求查询管理库。管理后台、数据库或采集链路故障时，已发布的外部站点代理继续执行；依赖业务数据库的表单/API、依赖实时鉴权的功能可能降级或拒绝，不能承诺这些功能全部可用。

两台服务器是职责拆分，不是高可用。B 故障会中断入口；需要高可用时增加第二入口节点、负载均衡与中间件冗余。

## 3. 统一数据、权限与发布

### 3.1 公共数据边界

所有业务对象携带 `tenant_id`、`site_id`、`environment`；子资源从已授权父资源定位，不接受客户端任意指定租户。环境继承站点且不可原地修改；测试内容通过复制草稿和重新审批进入生产，不能修改环境字段绕过发布。

复用现有 `sp_site`、`sp_site_member`、`sp_site_target`、`sp_domain_binding`、`sp_resource_audit`。新增表按子系统独立迁移，以下为拟定逻辑名称，编码阶段核对现有库后固化：

| 子系统 | 拟新增模型 |
| --- | --- |
| 发布 | `sp_change`、`sp_approval`、`sp_release`、`sp_release_artifact`、`sp_release_node_ack` |
| 路由 | `sp_route_rule`、`sp_route_target_weight`、`sp_certificate`、`sp_traffic_policy` |
| 站点搭建 | `sp_site_template`、`sp_page`、`sp_component_version`、`sp_site_setting`、`sp_form` |
| 流程 | `sp_workflow_version`、`sp_workflow_instance`、`sp_workflow_task` |
| 数据与 API | `sp_data_model`、`sp_field_policy`、`sp_api_definition`、`sp_api_version`、`sp_api_client`、`sp_api_scope`、`sp_api_attempt` |
| 统计 | `sp_metric_hour`、`sp_metric_day`、`sp_event_cursor`；请求明细使用轮转日志或后续专用存储 |

### 3.2 权限

保留现有 ADMIN、EDITOR、VIEWER，新增发布和审批的独立权限及审批人规则；平台权限与站点授权同时满足才可操作。生产提交者不能审批自己的变更；高危发布使用双人复核。审批人、发布人和 AI 工具身份分别留痕。

字段权限区分读取、创建、更新、筛选、排序、导出和脱敏；服务端在每个入口执行。隐藏按钮不算权限控制。未知字段和无写权限字段提交时返回明确错误，不能靠批量绑定对象写库。

审计以追加记录保存，业务角色不可修改或删除。生产业务数据库账户需要逐表最小授权；库级 UPDATE/DELETE 权限必须先处理，否则给审计表单独授权无法实现禁止修改。审计不承诺防止数据库超级管理员篡改，重要记录可异机追加归档。

### 3.3 发布与回滚

统一生命周期：草稿 → 校验/模拟 → 提交审批 → 审批通过 → 生成不可变发布包 → 节点加载 → 生效确认。审批绑定内容摘要及基础版本，编辑后审批失效；并发发布使用基础版本检查避免覆盖。

发布清单固定引用：域名、路由、目标、页面、菜单、表单、组件、流程、API 的具体版本及数据库兼容级别。不能只锁定页面版本、运行时却读取最新组件或最新 API。

节点状态区分待生效、部分生效、已生效、失败。加载前校验内容摘要、认证、结构与资源引用，先准备后原子切换。失败保留最近有效版本；生产页面与旧 API 保留兼容窗口。撤销域名或凭证需走独立紧急撤销策略，不能因节点持有旧配置而无限继续使用。

回滚是重新发布历史兼容快照，产生新发布记录。**配置回滚不撤销已写入的表单数据、不回退数据库结构、不自动撤销外部 API 副作用。** 数据恢复单独通过备份、兼容迁移或补偿流程完成；不可兼容版本不允许点击回滚直接上线。

## 4. 域名与分流：逐项实现

| 编号 | 需求 | 实现方案 | 验收标准 |
| --- | --- | --- | --- |
| D1 | 域名绑定站点 | 复用登记和 TXT 验证；增加证书、DNS 指向、入口接入检查及待接入/可发布/运行中/异常状态。证书先提供运维上传/部署与到期提醒；私钥不在普通接口返回 | 未验证域名、无匹配有效证书或无默认目标禁止发布；HTTPS 请求实际进入所属站点，未知域名拒绝 |
| D2 | 按域名、路径、地域、用户组分流 | 新建规则编辑、匹配模拟和独立执行服务；每条规则可组合条件，满足全部条件才进入其目标权重集合 | 为域名、路径、地域、组、匿名、未知地域分别准备固定测试请求；模拟和真实执行结果一致，伪造组信息无效 |
| D3 | 灰度、回滚、维护页 | 按站点匿名标识/登录标识稳定分桶；支持 90/10、50/50、全量；配置维护页及恢复；发布包与实际运行版本可查 | 同一访客在同一规则版本稳定命中；无效目标不接收流量；回滚恢复指定兼容版本；维护返回 503 和配置的 Retry-After |
| D4 | 路由规则版本化 | 草稿差异、变更理由、审批、版本摘要、执行节点确认和历史快照 | 编辑草稿不改变线上；审批后改内容必须重审；旧快照不被原地覆盖；部分节点失败可识别 |

### D2 匹配和执行约定

1. 精确匹配规范化主机名定位唯一域名绑定，再进入对应站点；未知 Host 不回落到后台或其他租户。
2. 先执行站点维护策略，再匹配普通规则；规则按显式优先级从高到低排序，优先级重复拒绝发布。路径支持精确和路径段前缀；`/app` 前缀不匹配 `/apple`；暂不开放任意正则。
3. 单条规则内域名、路径、地域、用户组条件为 AND；同一条件内多个取值为 OR。规则优先级由编辑者明确设置，模拟页面展示遮蔽/冲突及选择理由。
4. 命中首条规则后，对该规则健康目标集合分桶；权重为非负整数且总和为 100。分桶键采用站点作用域标识 + 规则稳定盐，避免使用 IP 直接代表用户。规则修改明确展示可能重新分配的影响。
5. 无匹配规则走站点默认目标；命中规则无健康目标时只使用该规则明确配置的同站点备用目标，否则返回 503，不能借故障跨站点转发。
6. 地域来自可信来源 IP 与本地 IP 地理库，按国家/地区、省级维度起步，明确存在识别误差；无法识别标记 UNKNOWN，按规则明确走默认或拒绝。只信任配置的入口代理链，清除外部伪造的 X-Forwarded-For。
7. 用户组来自站点登录体系的已验证令牌或受信身份适配器，校验签名、issuer、audience、有效期和站点范围；不能直接复用“后台管理员角色”，不能信任客户端自传 group 请求头。匿名用户独立分组。
8. 分流只决定路由，目标 API 仍独立进行身份与数据授权，防止把用户组路由当成访问控制。

### 反向代理运行要求

- 浏览器保留业务域名；每个目标显式指定上游 Host、TLS SNI、原路径保留或前缀重写。校验证书，不关闭 TLS 验证换取可用性。
- 上游必须识别外部 HTTPS 域名；验收 Location、Cookie Domain/Path/Secure/SameSite、登录回调和绝对资源链接。优先在上游配置公开域名，不进行通用 HTML 内容替换。
- 禁止 hop-by-hop 头及客户端伪造的内部身份头透传；管理员域名与业务站点 Cookie 和路由隔离。
- 目标 DNS 解析、重解析和重定向均做地址策略校验。默认拒绝环回、链路本地、云元数据和未批准私网；确有内网目标时按运维批准的目标地址与端口白名单开放，不能信任任意用户输入的 URL。
- 代理以流式方式处理请求和响应；配置连接、响应、上传超时和大小限制。WebSocket/SSE、分块响应、大文件、断连和背压纳入测试，不能将完整响应缓冲在 JVM 内存中。
- 默认不跟随上游重定向；如需改写 Location，限定为同站点批准目标。健康检查只检查批准的协议/端口/路径，设置超时与熔断。
- 无有效快照时拒绝提供业务路由；磁盘坏快照不能覆盖当前有效版本。管理库故障不妨碍读取本地有效快照。

## 5. 多站点管理：逐项实现

| 编号 | 需求 | 实现方案 | 验收标准 |
| --- | --- | --- | --- |
| S1 | 站点模板 | 模板包含页面、菜单、表单、组件及配置 schema；按模板版本复制生成新站点草稿，凭证、域名和成员不复制 | 同一模板创建两个站点后互不影响；模板升级先显示差异，不能自动覆盖已发布站点 |
| S2 | 页面、菜单、表单、流程 | 增加独立站点设计器与运行时；页面 JSON schema、站点菜单、受控表单数据绑定；流程定义与实例分开存储 | 能从模板创建页面、配置菜单、提交表单并进入审核流程；未授权直调接口被拒绝；站点 A 的菜单和数据不出现在 B |
| S3 | 公共组件与站点配置 | 组件白名单注册、版本固定、属性 schema、主题及站点设置；公共组件引用具体版本 | 发布组件新版本不影响旧页面；主题与语言等设置只对所属站点生效；密钥不下发浏览器 |
| S4 | 草稿、发布、回滚 | 页面、菜单、表单、流程及依赖按统一发布清单交付；预览使用短时签名凭证，绑定用户/站点/草稿版本 | 草稿仅有权人员可预览；发布后匿名访问只读已发布产物；回滚旧页面不删除新提交数据；流程实例仍使用启动时版本 |

### 页面与流程边界

站点同时支持“代理已有网站”和“平台托管页面”两种来源，同一个站点可按路径组合；路径冲突需发布前校验。JEECG 后台在线表单可以作为配置与数据模型的候选复用来源，不能未经适配就暴露管理端给公众。

页面第一批组件：容器、文本、图片、按钮、导航、表格、表单和指标卡；支持响应式布局、受控表达式、表单校验及授权数据源。不提供任意 JavaScript、任意 SQL、服务器脚本或自由安装插件。富文本做清洗，组件资源采用固定版本。

流程第一批节点：开始、人工审核、条件分支、受控 API 调用、通知任务和结束；保存状态迁移、处理人及操作记录，覆盖退回/驳回/取消、超时与失败处理。通知接入仅配置通道，实际业务消息须由已授权流程触发。并行会签、复杂 BPMN、任意脚本作为后续扩展，不作为第一批流程的隐含承诺。

已有流程实例固定引用流程版本；发布新版本只影响新实例。若引入第三方流程/报表/设计器组件，先验证依赖、安全和许可，不能把商业附加组件默认计为开源基线已具备。

## 6. 统计分析：逐项实现

| 编号 | 需求 | 实现方案 | 验收标准 |
| --- | --- | --- | --- |
| T1 | 访问量、独立访客、来源 | 入口请求日志统计请求量；页面运行时或已有网站 SDK 采集 page_view；站点范围匿名访客标识；来源使用裁剪后的 Referer 与允许的 UTM 字段 | 固定数据集能核对请求数、PV、UV；静态资源不算 PV；未接 SDK 的站点显示“仅入口请求”，不能标为完整 PV |
| T2 | API 调用量、错误率、延迟 | 采集所有受管 API 的请求数、认证/限流/业务/上游错误、总耗时、上游耗时及直方图；区分逻辑调用和重试次数 | 200/400/401/403/429/500/超时样本口径正确；展示 p50/p95/p99；重试不重复计为多个业务调用 |
| T3 | 分站点、租户、域名 | 服务端授权过滤；按时间、租户、站点、域名、规则、目标、发布版本聚合 | 两租户相同域名筛选条件仍不越权；域名更换归属后历史事件仍按发生时租户归属查询 |
| T4 | 审计与操作追踪 | 统一 change_id、release_id、request_id 和 trace_id；串联编辑、审批、发布、节点确认、回滚和 API 尝试 | 能追溯“谁将哪个版本发布到哪些节点”，能从错误指标进入脱敏请求详情；业务角色不可改删记录 |

### 指标口径与链路

- 请求量：入口处理的 HTTP 请求，分别标识页面、资源、健康检查和 API。PV：成功接受的页面浏览事件，SPA 路由变更由 SDK 上报；单纯 HTTP 代理不能识别所有前端页面浏览。
- UV：站点范围匿名标识在查询时间范围去重；不跨站点追踪。删除 Cookie、换浏览器、拒绝标识都会影响准确性；没有标识时仅计 PV，不用 IP 冒充精确 UV。日 UV 不可直接相加得到月 UV。
- 错误率：分别展示 5xx/全部请求、4xx/全部请求、应用失败/逻辑调用及入口失败；维护流量、机器人、健康检查独立标签，默认排除并可切换查看。
- 延迟：说明是入口总耗时还是上游耗时；失败及超时单独统计。p95 使用原始分布或可合并的直方图计算，不能对每小时 p95 再求平均。
- 来源：缺失 Referer 标记直接/未知；只保留来源主机及允许的营销字段，默认不保留完整查询参数，不记录 Token、Cookie、表单正文和密钥。
- 明细落 B 的独立轮转日志，带事件 ID；采集器发送到 A 的受控 Redis Stream，聚合任务通过批次游标事务提交指标。SDK 事件做去重，批次重投不能重复累加；进程重启恢复消费位置。
- B 的缓冲区有大小与磁盘水位上限；A 不可用时短期落盘恢复，容量耗尽允许丢弃统计并记录缺口，绝不阻塞业务代理。不能同时宣称“统计绝不丢失”和“任何故障下不阻塞”。
- 初始保留策略建议：请求明细 7 天、分钟/小时指标 90 天、日指标 1 年、审计 1 年；可按容量与业务要求修改。UV 精确去重或近似结构必须与保留窗口一致，查询窗口外明确提示不可用。
- 初期用 MySQL 聚合表；上线前压测得到每秒请求量、事件量、索引增长、聚合延迟和磁盘预算。超出容量后将明细/去重迁移到专用分析存储，管理库不承担无限明细写入。

## 7. 定制 API 平台：逐项实现

| 编号 | 需求 | 实现方案 | 验收标准 |
| --- | --- | --- | --- |
| A1 | 数据模型与字段权限 | 模型、类型、校验、索引、关联和模型版本；受控 CRUD API；服务端执行租户/站点/行/字段授权 | 新模型可在测试环境生成查询与写入接口；越权字段不能读写、筛选、排序或导出；生产模型变更需迁移审批 |
| A2 | API 路由、参数、响应模板 | API 定义固定 method/path、入参 schema、授权数据源和响应 schema；参数绑定使用白名单；响应模板只允许映射与受控计算 | 参数缺失、类型错误、超长或未知字段有稳定错误；冲突路由拒绝发布；禁止从请求输入原样构造任意 URL 或 SQL |
| A3 | API Key、OAuth、限流 | 应用凭证按租户/站点/environment/scope 授权；轮换、撤销、到期；OAuth 对接身份提供方；Redis 原子限流与本地保护 | 过期/撤销/越权凭证拒绝；伪造 scope/租户无效；超限返回 429；Redis 故障按既定策略拒绝或受限服务，无无限放行 |
| A4 | 版本、OpenAPI 文档 | 显式 `/api/v1`、`/api/v2` 与不可变操作版本；文档由发布契约生成、受授权访问；记录弃用窗口与调用者 | 文档与实际参数/响应/认证一致；v2 发布不改写 v1；不兼容变更阻断原版本发布；到期下线前可查依赖应用 |
| A5 | 调用日志与失败重试 | 逻辑调用与每次尝试关联；记录脱敏状态、耗时、版本和追踪 ID；退避、抖动、次数与总时限；异步重试任务持久化 | 超时和失败可定位；普通非幂等写入不自动重试；幂等键并发/重复请求只产生一次受控业务效果；超限进入失败队列并可授权重放 |

### API 实现边界

1. 现有 JEECG AK/SK、IP 白名单、授权及日志代码先做隔离与安全核验后复用。AK/SK 签名、API Key 和 OAuth 是不同机制，分别建模，不将现有 AK/SK 页面当作 OAuth 完成。
2. 普通 API Key 随机生成、仅展示一次、服务端保存不可逆摘要与公开标识；若保留 AK/SK 对称签名机制，服务端需使用受保护密钥存储并做时间窗和重放检查，不能只存哈希却又要求恢复密钥验签。
3. OAuth 优先对接已有身份提供方；无现成服务时部署经核验的开源授权服务作为单独组件，纳入 A 的容量和备份预算。授权服务产品与版本需要在该子系统设计阶段根据部署约束锁定，不自写一套 Token 签发协议。
4. 用户交互采用授权码 + PKCE，服务间调用采用 client_credentials；校验 issuer/audience/签名/有效期/scope，设置密钥轮换和撤销传播上限。不把浏览器中的 client_secret 作为安全边界。
5. API Scope 与站点、模型、操作相交授权；OAuth 认证不能替代数据权限。租户由凭证/可信身份确定，不能靠请求传 tenant_id 获得权限。
6. 限流维度包括租户、应用、API、用户/IP，设置并发和单位时间配额。Redis 故障时高危写 API 默认拒绝并返回可重试错误；公开只读 API 可使用保守本地额度。客户端看到的 429 与基础设施故障 503 分开。
7. 模型先支持受控字段与常见关系，不承诺任意 SQL 自动生成高性能业务接口。复杂事务及跨系统副作用使用审核后的代码扩展接口。生产 DDL 独立迁移，优先兼容增量修改；删列、改类型和批量重算单独审批与备份。
8. 重试仅用于明确可重试错误，例如连接失败、429/502/503/504；遵守 Retry-After 和总截止时间，默认最多 3 次总尝试，参数可配置。读请求也要确认业务幂等；鉴权失败、校验失败和一般 4xx 不自动重试。
9. 对写入接口，仅声明幂等并实现服务端幂等键约束后允许重试。键作用域包含租户/应用/接口版本，绑定请求摘要；同键不同内容拒绝。外部系统没有幂等保证时不能承诺端到端恰好一次，保留未知结果状态和人工核对流程。
10. 重试任务绑定接口与流程版本，禁止一条业务请求在客户端、代理、流程和后台多层叠加重试。凭证撤销后重试仍须重新授权，历史任务不豁免权限。

## 9. 分阶段交付与依赖

| 阶段 | 内容与需求编号 | 前置依赖 | 独立可验收结果 |
| --- | --- | --- | --- |
| P0：补齐资源验收 | 已有资源、生产授权、真实域名与多账号验证 | 当前资源代码 | 域名、站点及角色隔离证据完整 |
| P1：基础代理与发布 | D1、D2 的域名/路径、D4、公共发布与节点 | P0 | 一个真实域名通过 HTTPS 代理两条路径；草稿/审批/发布/回滚闭环；后台停止代理仍可运行 |
| P2：完整分流策略 | D2 的地域/用户组、D3、权重、健康/备用与维护 | P1；可信站点身份适配 | 能稳定灰度、按地域与身份组命中；故障/维护/回滚可演练 |
| P3：统计与追踪 | T1—T4 的采集、维度、审计；API 指标基础 | P1，可与 P2 后半并行 | 代理请求可查，接 SDK 的站点有 PV/UV；追踪到规则及版本；采集故障不阻塞代理 |

| P5：站点搭建与运行时 | S1—S4，基础流程 | P1 发布；P4 授权数据源 | 从模板创建两个独立站点，表单提交并审核，发布及兼容回滚 |
| P6：API 完整治理 | A3 的 OAuth、A5，补齐 T2/T4 | P4；身份服务和幂等契约 | OAuth 接入、撤销/限流、异步重试与故障重放可验证 |
| P7：综合上线验收 | 全部 17 组需求联测、压测、备份恢复和部署 | P0—P6 | 按验收矩阵签收，生产配置与恢复步骤可复现 |

这是功能建设顺序，不是删减需求。P5 依赖受控 API 以避免页面设计器另造数据权限；P6 的基础重试契约须在 P4 预留，不能上线非幂等写入自动重试后再补。

实施工作包分成资源接入、发布、执行器、统计、数据/API、站点运行时、OAuth/重试七个子系统，分别形成可独立评审的设计与逐文件计划。当前不把整个完整平台直接塞入一份编码任务清单。

## 10. 总体验收与运行目标

以下为建议的首轮验收目标，需在约定数据规模及压测环境记录实测结果，不能当作当前已实现性能：

- 发布：健康的单节点在提交后 30 秒内确认；确认超时不显示已生效，失败不替换有效快照。配置回滚目标 60 秒内完成并有节点确认。
- 分桶：固定规则版本下同一访客结果稳定；用至少 100,000 个独立测试标识核对权重，10% 目标的占比偏差不超过 1 个百分点；健康目标集合变化单独记录。
- 统计：正常链路聚合延迟目标不超过 60 秒；故障恢复后批次不重复累计，超出缓冲时明确报告数据缺口。
- 安全隔离：两租户、每租户两站点、管理员/编辑/只读/审批/API 客户端逐接口验证读取、写入、导出、批量和预览；新开放入口必须同步补测。
- 代理兼容：HTTPS、路径改写、Cookie、登录回调、WebSocket/SSE、大文件、重定向、超时及未知域名；没有兼容证据的上游不能标为可接入。
- 故障：停止后台、停止 Redis/MySQL、断采集、磁盘水位触发、坏快照、过期证书、节点重启、上游全失败；分别核对代理、表单/API、鉴权和统计的退化结果。
- 回滚：页面和路由回滚可重放；业务数据不丢失；不兼容数据库版本被阻断；工作流老实例继续使用旧定义。
- 恢复：A 的数据库、B 的发布产物/上传/快照及必要密钥配置分开备份；在隔离环境实际恢复。建议初始业务数据 RPO 24 小时、RTO 4 小时作为待实测目标；需要更短 RPO 时必须增加 binlog 归档与恢复演练。
- 容量：用实际目标并发和请求体分布确认 B 上代理、后台、页面运行时共存时的 CPU/内存/连接预算。没有业务流量基线前不承诺固定 QPS，也不把原两台 4 核 8 GB 的初期建议当作完整平台容量保证。

生产运维沿用 `docs/deployment/two-server-deployment.md`，P1 起另补执行器 systemd、节点凭证、本地快照与日志目录；P5 补页面产物，P6 若无现成身份服务再补授权服务部署。现有部署模板不会因本文自动获得这些服务。

## 11. 外部规范与核验依据

技术选型仍需结合锁定版本做集成验证，以下仅为设计依据，不证明本项目已实现：

- Nginx 官方 split_clients 文档：说明基于哈希进行 A/B 分桶；本项目仍须实现站点作用域标识、权重校验、健康切换和版本行为。`https://nginx.org/en/docs/http/ngx_http_split_clients_module.html`
- OpenAPI 3.1 规范：用于生成契约、参数、响应及 apiKey/oauth2 安全定义；文档描述不替代后端授权实现。`https://spec.openapis.org/oas/v3.1.html`
- RFC 9700：OAuth 安全实践，作为授权码 + PKCE、重放防护及令牌策略核验依据。`https://www.rfc-editor.org/rfc/rfc9700.html`
