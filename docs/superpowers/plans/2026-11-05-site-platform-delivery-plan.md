# 多站点与分流平台分阶段交付计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement each approved subsystem plan task-by-task. Track steps with checkboxes.

**Goal:** 交付可验证的域名、站点、基础分流、统计和受控配置发布闭环。

**Architecture:** JEECG 管理后台、独立流量执行服务、异步采集链路。统一变更流程，发布不可变配置快照；AI 先在测试环境提交提案。

**Tech Stack:** JeecgBoot 开源版 v3.9.5，同标签 Vue3 前端与单体后台；Java 21 为建议验证运行时。网关、数据库及采集组件在源码基线阶段核验并记录后锁定。生产发布须通过 `docs/baseline/version-selection.md` 的组件安全与构建验证。

## Global Constraints

- 首期站点代表已有网站及其目标地址，不包含完整网站页面搭建器。
- 自然语言操作先限定在测试环境，通过受控接口生成变更草稿。
- 首期承诺配置版本回滚。
- AI 无生产发布凭证、数据库直连权限、任意脚本执行权限及插件安装权限。
- 后台不可用或采集失败不得阻断已发布路由。

## 计划精度

2026-11-06 完整范围补充：用户要求对域名/路径/地域/用户组分流、站点模板与页面流程、完整统计和 API 平台逐项给出建设方案，并确认使用反向代理保留访问域名。完整的 17 组需求、验收标准与扩展交付顺序见 `../specs/2026-11-06-full-site-platform-solution.md`。该补充是建设方案，不代表以下未完成能力已交付，也不取代各子系统的详细实施计划。

这是跨子系统交付顺序，不是可以直接执行的代码变更清单。编写时尚未接入源码，故各阶段启动时根据真实仓库补充实现计划、确切文件和验证命令，再执行代码变更。2026-11-06 已有源码基线；资源阶段实施计划见 `2026-11-06-site-resources-implementation.md`。

## 阶段 0：建立源码与能力基线

交付文件：`docs/baseline/source-and-license.md`、`docs/baseline/capability-matrix.md`、`docs/baseline/local-runbook.md`。

- [ ] 从官方仓库选择可复现的发布版本，记录仓库、标签、提交和许可证，以及附加组件来源与使用限制。
- [ ] 核对用户、角色、租户、字段权限、API、报表和 AI 功能，逐项标记原生可用、需要扩展或不纳入首期。
- [ ] 盘点本机运行依赖，按该版本官方说明启动后台与前端，记录真实命令、健康检查结果及关闭方式。
- [ ] 输出源码目录对应关系及阶段 1 的实现计划。

2026-11-06 进展：已接入 v3.9.5 完整提交，许可证与组件范围盘点见 `docs/baseline/source-and-license.md`，源码能力矩阵见 `docs/baseline/capability-matrix.md`。后端打包、独立数据库/缓存、前后台开发入口已验证，详见 `docs/baseline/local-runbook.md`。阶段 1 先形成 `2026-11-06-resource-isolation-checklist.md`，确切代码计划仍须结合资源模型细化。依赖的逐包授权与生产安全审查尚未完成，所以以上综合任务保留未完成标记。

验收：版本可复现，授权范围可辨认，最小后台可运行；所有后续能力均有来源或定制任务。

## 阶段 1：资源与隔离

依赖：阶段 0。交付租户、站点、域名归属及后端授权。

- [ ] 定义资源标识、租户与站点归属、环境字段及主机名唯一约束。
- [ ] 实现站点登记、目标地址登记、域名验证与资源授权。
- [ ] 使用两个租户及多角色验证读、写、导出和批量接口均不能跨边界访问。

验收：无授权的数据访问被服务端拒绝；未验证域名不能进入可发布配置。

2026-11-06 进展：已交付站点/目标/域名登记、DNS 挑战与验证、站点 ADMIN/EDITOR/VIEWER、租户成员核验及资源操作记录。21 项定向测试含真实 MySQL、跨站点访问和并发撤权回归通过；前后端打包与本地菜单、资源面板验收通过。安装见 `docs/deployment/site-resources-runbook.md`。首期暂不开放导出、批量接口或 AI 工具；完整公共 DNS、真实多角色浏览器及生产最小授权仍需验收，所以不将本阶段综合验收全部勾选为完成。发布前域名校验由后续发布模块接入。

## 阶段 2：配置发布与基础分流

依赖：阶段 1。交付独立入口服务及不可变配置发布闭环。

- [ ] 在子系统设计中确定首期转发语义、路径匹配、优先级、权重算法、默认目标及可信代理边界。
- [ ] 定义包含租户、站点、环境、版本、内容摘要与规则的快照契约，以及节点确认契约。
- [ ] 实现草稿、冲突校验、模拟、版本绑定审批、发布记录和节点生效确认。
- [ ] 实现入口读取快照、最近有效版本持久化及重启恢复。
- [ ] 验证后台停止、采集失败、部分节点更新失败、审批失效、回滚和非法目标拒绝。

验收：草稿不影响线上，分流结果确定，故障时保留有效配置，失败与回滚均可追溯。

## 阶段 3：统计、API 管理与审计

依赖：阶段 2。交付访问采集、API 授权与限流、变更追踪。

- [ ] 定义访问事件与 API 指标字段、匿名访客口径、保留期限及敏感字段过滤。
- [ ] 实现异步采集与按租户、站点、域名查询的看板，验证隔离和采集故障不影响入口。
- [ ] 对固定业务接口加入凭证生命周期、服务端资源授权、限流及调用记录。
- [ ] 将提交、审批、发布、节点结果和回滚关联到同一变更记录。
- [ ] 验证越权凭证、已撤销凭证、超限请求和普通业务角色修改审计的尝试均被拒绝。

验收：统计和调用异常可查询，敏感凭证不进入日志，审计能完整定位变更及生效版本。

## 阶段 4：测试环境 AI 与恢复演练

依赖：阶段 3。交付受控提案入口和恢复记录。

- [ ] 建立测试环境独立凭证与工具白名单，定义提案输出结构及风险分类。
- [ ] 实现自然语言生成草稿、差异展示、校验和受控执行。
- [ ] 验证提示注入、修改环境参数、越权调用、脚本执行和生产写入均无法突破服务端边界。
- [ ] 在测试环境执行配置回滚及备份恢复演练，记录恢复点、过程和结果。

验收：AI 可完成授权范围内的测试草稿操作，无法触及生产写权限；恢复步骤可复现。
