# 应用共享配置与升级说明

本次将应用管理的“转移”改为“共享”：创建者保留查看、编辑、删除和管理共享的权限，接收者只能查看、导出及编辑被共享的应用，仍需具备相应菜单、按钮和字段权限。共享不更换应用业务用户编号或数据归属。

## 后台使用

1. 管理员在业务身份管理中为接收者开通当前租户的业务身份，并分配应用查询、编辑等所需权限。
2. 创建者或当前租户管理员进入应用管理，点击应用行的“共享”，或选择最多100个有管理权限的应用后批量共享。
3. 选择接收人并填写原因。单个应用的共享弹窗同时展示接收者、撤销入口及操作审计。
4. 撤销后，接收者不能继续读取或提交该应用；已停用、退租或删除的接收者也可被撤销。进行中的编辑与撤销通过事务锁串行处理。

普通用户看到自己拥有的应用和明确共享给自己的应用。接收者不能删除、转授或管理共享，即便其角色拥有通配操作权限。管理员须具备有效的 `admin` 角色，可查看当前租户已登记归属的应用；不会跨租户展示数据。

共享不扩大商店记录、统计、日志、PWA、风控等独立资源的权限。接收者的自动拉黑入口隐藏，应用编辑过程中补建的商店记录仍归原应用所有者。

## 升级顺序

先备份数据库和现有构建产物，再执行包模块迁移 `014-app-sharing.sql`，最后发布配套的后端与前端。迁移可重复执行，新增 `pkg_app_share`、`pkg_app_share_audit`，仅将原按钮名称更新为“共享”，保留权限标识与已有角色授权。

迁移文件：`upstream/JeecgBoot/jeecg-boot/jeecg-boot-module/jeecg-module-package/src/main/resources/db/package/014-app-sharing.sql`。

管理员应按业务需要为角色配置 `package:apps:query`、`package:apps:edit`、`package:apps:transfer` 等权限；共享接收者不必获得 `transfer` 权限。迁移不自动给普通角色授权。管理员数据范围不再由 `package:*` 通配权限决定。

## 接口兼容与审计

新接口位于 `/package-admin/apps`：`POST /shares`、`POST /shares/revoke`、`GET /{id}/shares` 和 `GET /{id}/share-audit`。写入参数为 `ids`、`targetUser`、`reason`；ID支持JSON字符串，原因必填且最多500字符。写接口返回实际变更数量，重复共享或撤销不重复写审计；混入无权限应用的批次整体失败。

旧 `POST /transfer` 保留并改为共享；旧客户端未传原因时使用兼容入口说明。列表与审计返回 `{records,total}`，当前为全量返回、前端本地分页。审计记录操作人、接收者、原因和时间，撤销或删除应用后保留数据库记录；删除后的应用不再提供原应用弹窗查询。

历史已经执行的真正归属转移无法仅凭当前数据还原原创建者，本次不会猜测或自动修改历史归属；需要原用户继续访问时，由当前所有者或管理员显式共享。
