# 白名单地区国家码迁移（2026-11-10）

## 来源与范围

源项目 `D:/workspace/package-api/package-api` 的 dev 提交 `0f83f8128df8c9978c49479775f86fa716fb435d` 中，`PackClient/src/constants/whitelistAreaLinkage.json` 提供 75 个中文名称/别名，对应 49 个不同国家或地区。源 SQL 没有提交 `app_area` 的数据库字典记录，因此不能断言这 49 项包含原线上所有自定义字典项。中文名称同时参考源 `PackServer/sql/app_pack_stat.sql`；包统计的其他国家名称仅作历史别名兼容，不会全部加入白名单选项。阿联酋及其中文全称修正源配置错字，错字继续作为别名读取。

## 已实现规则

- 当前 JEECG 字典编码 `app_area`，值统一小写两位国家码，文本为中文；不改变应用的地区限制开关和现有风控顺序。
- 新建、编辑、导入和 OpenAPI 经应用服务保存时，将中文/繁体别名及大写国家码转成小写码，去空格、去重。显式空字符串可以清空；null 仍保留原有“不修改”语义。
- 11 个旧协议实现及四段路径风控统一按国家码匹配，优先使用 Geo 返回的 `countryCode`，不再依赖 Geo 的中文名称。国家码缺失时仅兼容已知中文名称。
- 保留旧标量 Geo 查询中“被阻止的运营商按美国处理”的政策；四段路径继续保持自己的原有风控顺序。
- `/home/index/jsp` 和数字路径的备注多地区链接接受国家码键，兼容中文键；同一地区同时存在时优先小写国家码键。客户端编码、加密和返回结构保持原有实现，`/app/start` 的 `user` 地区值同步规范为国家码。
- 统计子地区分流也使用同一匹配规则，编辑器用同一中文地区选项，保存国家码。
- 不能识别的历史文字原样保留供核查，不能与未知访客地区匹配，不会自动放宽访问。
- 前端优先读取字典并规范旧值，字典暂不可用时使用这 49 项作为显示选项。表格、编辑器保持 JEECG 样式。前后端映射资源通过回归测试检查一致性。

## 部署与数据迁移

3. 脚本补齐 49 项字典，转换原中文字典项及已存应用/统计地区，处理重复字典项。额外自定义项保留；49 项中重复值仅保留一条启用记录。
4. 原始地区保存到 `pkg_country_area_backup`，原字典项保存到 `pkg_country_dict_item_backup`，重复执行不覆盖首份备份。对超出 256 个逗号分隔项的异常记录不做转换，应人工核查。
