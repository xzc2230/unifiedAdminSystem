# 菜单中文乱码排查与修复

日期：2026-11-09。影响部署：13.222.19.112 当前应用包管理菜单及操作权限名称。

## 根因

菜单SQL文件和前端源文案均为正确UTF-8。部署导入时未指定客户端字符集，服务器MySQL容器内CLI默认client/connection/results为latin1。原菜单SQL没有SET NAMES，中文UTF-8字节被按latin1解码后写入sys_permission.name，形成“åº…”式乱码。该列为utf8mb3，能够保存这些中文；本次不需要修改列字符集。

此前菜单验证只核对ID、数量和组件路径，没有校验中文名称，因此漏检。

## 已执行修复

- 先在服务器MySQL临时表复现：原脚本以latin1导入，80项名称全部不匹配；增加SET NAMES utf8mb4后，以latin1启动的客户端连续导入两次，80项名称均精确匹配。
- 备份80条受影响sys_permission记录至服务器`/opt/unifiedAdminSystem/backups/menu-encoding-20261109T072705Z/sys_permission-package.sql`，目录700、文件600。
- 事务内按80个明确稳定ID，仅将name恢复为规范名称。采用UTF-8十六进制字面量，避免传输编码二次污染。修复后80项名称全部精确匹配；其他菜单字段、非迁移菜单名称及全部角色授权的前后摘要一致。
- 通过正常验证码及管理员登录获取前端实际使用的权限API，确认“应用包管理”根菜单和13个子菜单的meta.title全部与规范中文名称相等。未打印令牌或凭据。没有执行浏览器交互验收。

## 防止再次发生

- 菜单种子在事务开始前明确SET NAMES utf8mb4；部署命令同时指定`mysql --default-character-set=utf8mb4`。
- 提供`deploy/package-api/repair-menu-names.sql`供已有乱码部署使用；只恢复已存在的80项标准名称，不重新授权或覆盖路由。
- 增加回归测试校验种子字符集声明、修复脚本80项名称与种子一致、仅更新name且采用ASCII十六进制；字符集声明测试已先失败再修复通过。
- 前端当前会话可能仍缓存原菜单，请退出登录后重新登录，重新获取动态菜单。

本次修复代码、修复SQL及回归测试随本次Git提交保存；线上数据库名称已修复，不需要重建前后端才能看到正确菜单。最终前端测试13项全部通过。
