# 应用包管理没有子菜单

2026-11-09线上排查：管理员权限API返回根菜单和13个子菜单，子菜单未被隐藏；根菜单component却为`layouts/default/index`。

宿主`transformObjToRoute`仅把`LAYOUT`识别为目录布局。其他值触发普通页面包装：根path改为空、设置meta.single，并把原树包进单页面节点。后续菜单转换与渲染因此无法按预期显示目录下13个子菜单。此前测试检查了API子菜单数量和归一化，缺少实际宿主路由转换验证，未发现此配置错误。

修复包括：菜单种子根component改为LAYOUT；前端仅对/package-management根强制归一化为LAYOUT以兼容旧配置；提供仅调整既有根组件值的repair-menu-root.sql。

验证：新增测试编译并执行实际宿主transformObjToRoute函数，仅替换无关的组件加载依赖，覆盖LAYOUT和两种旧组件路径。修复前路径/单页面标记断言失败，修复后根路径正确、无single标记、13个直接子节点保留。前端完整14项测试通过。

线上先备份根记录，再事务更新该根的component；核对其他所有权限记录、根的其他字段、全部角色授权摘要均不变；正常管理员登录后权限API确认component为LAYOUT并有13个子菜单。浏览器真实交互尚未在本轮验证，用户需退出重新登录以清理已生成的旧路由。

数据库修复不依赖前后端重建；前端兼容性修复、种子修改及修复SQL随本次Git提交保存，前端兼容性代码尚未部署。
